# 本地服务健康看护插件（local.health-watch）

**装上就行，不用配置。** 它会自己发现你电脑上正在跑的本地服务，出问题时用麦麦的账号私聊告诉你。

---

## 它是干什么的

麦麦经常会用到一些**装在你电脑上的服务**：本地模型、语音合成、语音识别……
这些服务挂了**不会让麦麦崩溃**，但会让某些功能**悄悄失效**（发不出语音、听不了语音、
记忆写入降级……），日志里只有一行不起眼的提示，很容易过了好几天才发现。

这个插件每 5 分钟探一遍，**发现某个服务从"好好的"变成"叫不应"** 时，主动私聊告诉你，
并且**告诉你该怎么修**。

## 它管不了什么（很重要，请一定看）

> **它没法告诉你"麦麦自己挂了"。**

插件是跑在麦麦里面的 —— 麦麦没了，插件也没了，没人能报警。
所以"麦麦自己是否活着"必须靠**麦麦之外**的东西来盯（比如一个独立的小任务 + 另一个机器人）。

**这个插件负责的是：麦麦活着的时候，帮你盯着它依赖的那些服务。**

---

## 安装

把 `local_health-watch` 整个文件夹放进麦麦的 `plugins` 目录：

```
MaiBot/
└── plugins/
    └── local_health-watch/     ← 放这里
        ├── _manifest.json
        ├── plugin.py
        └── README.md
```

然后重启麦麦（或在 WebUI 里重载插件）。**不需要任何配置就能用。**

## 使用

### 1. 填一下告警发给谁（唯一需要做的一件事）

打开 **麦麦 WebUI → 插件 → 本地服务健康看护 → 配置**，填这一项：

| 配置项 | 填什么 |
| --- | --- |
| **告警接收人 QQ** | 你的 QQ 号（会私聊发给你） |

> 不填也行：插件照常检测，只是不给你发消息，只写进日志。

### 2. 就这样，没了

插件启动时会自动探测常见的本地服务，**谁能连上就盯谁**：

- ✅ 你装了 Ollama → 盯着 Ollama
- ✅ 你装了语音合成 → 盯着语音合成
- ✅ 你**没装** ComfyUI → **永远不会**因为 ComfyUI 报警（这是关键：没装的东西不吵你）

内置会尝试发现的服务（有哪几个就盯哪几个）：

| 服务 | 默认端口 |
| --- | --- |
| 本地模型（Ollama） | 11434 |
| 本地语音合成 | 8720 |
| 本地语音识别 | 8910 |
| GPT-SoVITS 语音 | 9880 |
| LM Studio | 1234 |
| vLLM / 本地推理 | 8000 |
| ComfyUI | 8188 |
| Stable Diffusion WebUI | 7860 |
| one-api / new-api | 3000 |

### 3. 在群里发 `/health` 可以立刻体检

```text
【麦麦体检】2026-10-01 07:35:02
✅ 本地模型(Ollama)：HTTP 200（2 个模型）
✅ 本地语音合成：ok=true
❌ 本地语音识别：ConnectError: 连接失败
```

## 收到告警是什么样

```text
【麦麦告警】本地语音合成 没回应
2026-10-01 07:31:22
探测：ConnectError: All connection attempts failed
（插件 local.health-watch；同类问题 60 分钟内只提醒一次）
```

**不会烦你的保障**：

- 只在**状态变化**时发（好→坏），不会一直重复发
- 同一个服务 **60 分钟内只提醒一次**
- 单次探测失败**不算掉线** —— 会重试 3 次（本地模型加载、语音合成长句时会短暂不响应）
- **发现阶段没连上过的服务永远不报警**（= 你没装的东西不会吵你）

## 需要更多控制时（可选，不懂就别动）

配置里有三个进阶项：

| 配置项 | 作用 | 例子 |
| --- | --- | --- |
| **自动发现** | 默认开。关掉后只盯你手动加的服务 | 保持开启即可 |
| **不要盯的服务** | 填一部分名字就会跳过 | 填 `语音` → 跳过所有带"语音"的服务 |
| **额外要盯的服务** | 手动添加内置清单以外的服务 | `我的数据库\|http://127.0.0.1:5432/\|修法：重启数据库` |

**「额外要盯的服务」格式**（每行一个）：

```text
显示名 | 网址 [ | 修法提示 [ | 判定方式 ] ]
```

- **显示名**：告警里显示的名字
- **网址**：探活会对它发一个 GET 请求
- **修法提示**：可选，会附在告警里
- **判定方式**：可选，三种
  - 不填（默认）：**能连上就算活着**（返回 404 也算，因为很多服务对首页就是 404）
  - `json_ok`：要求返回 `{"ok": true}`（适合自带 /health 的服务）
  - `ollama`：要求返回模型列表（适合 Ollama 的 /api/tags）

例子：

```toml
extra_targets = [
    "我的数据库|http://127.0.0.1:5432/|修法：重启数据库服务",
    "另一个模型|http://127.0.0.1:5000/v1/models|修法：跑 start-model.bat|json_ok",
]
```

## 配置项总表

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| `alert_user_id` | 空 | **告警接收人 QQ（建议填上）** |
| `auto_discover` | 开 | 自动发现本机在跑的服务 |
| `exclude_names` | 空 | 不想盯的服务名（填一部分即可） |
| `extra_targets` | 空 | 额外要盯的服务（进阶） |
| `enabled` | 开 | 总开关 |
| `interval_seconds` | 300 | 多久探一次（秒） |
| `cooldown_minutes` | 60 | 同一个服务的告警冷却（分钟） |
| `probe_attempts` | 3 | 单轮重试几次才算掉线 |
| `probe_gap_seconds` | 1.5 | 两次重试之间等多久 |

## 常见问题

**Q：装了但一个服务也没发现？**
说明你电脑上没跑内置清单里的那些服务（或者端口不是默认的）。
用「额外要盯的服务」手动加即可。

**Q：我改过端口，插件没发现怎么办？**
用「额外要盯的服务」手写一行，填你的实际地址。

**Q：告警没收到？**
1. 检查「告警接收人 QQ」是否填了；
2. 看麦麦日志里有没有 `（未配置 alert_user_id）本应告警：...`；
3. 可能是冷却期内（默认 60 分钟）；
4. 确认麦麦能给你发私聊。

**Q：能不能只报"恢复了"不报"故障"？**
可以，但要改代码（见下）。

**Q：会不会因为电脑上没装的软件一直报警？**
不会。**从没连上过的服务永远不会被报警** —— 这是这个插件最重要的设计。

## 给开发者的说明

| 想改什么 | 改哪里 |
| --- | --- |
| 增加/删减内置发现的常见服务 | 文件顶部的 `KNOWN_SERVICES` |
| 支持带鉴权头的探活 | `_probe_once()`（目前只发无鉴权的 GET） |
| 恢复时也通知 | `_tick()` 里加 `if previous is False and ok:` 分支 |
| 告警发到群而不是私聊 | `_send_alert()` 改用 `self.ctx.chat.get_stream_by_group_id(...)` |

**两个踩过的坑（改代码时注意）**：

1. **本地探测必须 `trust_env=False`**
   httpx 默认会读系统代理设置，连 `127.0.0.1` 都被代理接管 → 返回一个代理错误页（如 502）
   → 被"有响应就算活"的规则**误判成服务在跑**。实测踩过：本机只跑了 4 个服务，却报出 10 个。

2. **配置模型里必须有 `[plugin]` 节并带 `config_version`**
   否则宿主会拒绝加载（提示"配置版本非法"）。见 `PluginMeta`。

运行状态存在 `data/plugins/local.health-watch/state.json`，
记录了"发现过哪些服务""上次什么时候告警"，**所以重启麦麦不会导致重复告警**。
